# 2026-10-26 結帳優惠碼

來源：Issue #1（對應第四場作業 Issue A）。驗收測試：`tests/acceptance/coupon.test.js`（助教提供，不得修改）。

## User Story

作為會員，我希望在結帳時輸入優惠碼折抵商品金額，以便用更低的價格購買花束。

## Spec

### 優惠碼規則

規則集中在 `src/utils/coupon.js`（比照 `src/utils/shipping.js`：不依賴 Express 與資料庫的純函式）。

| 優惠碼 | 折扣內容 | 使用條件 |
|--------|----------|----------|
| `FLOWER100` | 折抵 100 元 | 商品小計滿 800 元（含 800） |
| `SPRING10` | 商品小計打 9 折，最多折抵 300 元 | 無門檻 |
| `SUMMER50` | 折抵 50 元 | 已失效，不可使用 |

- 每張訂單最多 1 組優惠碼；優惠碼不分大小寫，前後空白會去除，記錄時一律大寫。
- 優惠只折抵商品小計，不折抵運費；折扣金額四捨五入至整數（以整數運算，避免浮點誤差），且不會超過商品小計。
- 免運門檻（1,500 元，含）以**折扣後**的商品小計判斷。
- 訂單總額 = 商品小計 − 折扣 + 運費。

### API 規格

- `POST /api/orders` 新增選填欄位 `couponCode`（字串）。
  - 不帶、`null` 或空白字串：視為未使用優惠碼。
  - 不是字串（數字、陣列、物件等）：400 `VALIDATION_ERROR`（每張訂單最多一組，陣列也屬此類）。
  - 錯誤情境（皆為 400，`data: null`，不建立訂單、不扣庫存、不清空購物車）：

    | 錯誤碼 | 情境 |
    |--------|------|
    | `COUPON_INVALID` | 優惠碼不存在（含格式不符） |
    | `COUPON_EXPIRED` | 優惠碼已失效（`SUMMER50`） |
    | `COUPON_MIN_SUBTOTAL` | 商品小計未達使用門檻 |

  - 回應 `data` 新增 `discount`（未使用為 0）與 `coupon_code`（未使用為 `null`，使用時為大寫）；`subtotal` 為折扣前的商品小計。
- `GET /api/orders/:id` 回傳 `discount` 與 `coupon_code`；`GET /api/orders`、後台訂單 API 同樣帶出這兩個欄位。
- 綠界付款金額（`TotalAmount`）與 `check-payment` 核對的 `TradeAmt` 都是折扣後的 `total_amount`，不需另外處理。

### 資料庫變更

`orders` 新增兩個欄位：

| 欄位 | 型別 | 說明 |
|------|------|------|
| `discount` | `INTEGER NOT NULL DEFAULT 0 CHECK(discount >= 0)` | 折扣金額 |
| `coupon_code` | `TEXT`（可為 NULL） | 使用的優惠碼（大寫） |

- 新資料庫：直接在 `CREATE TABLE` 定義。
- 既有資料庫：以可重複執行的 migration 先檢查欄位再 `ALTER TABLE`；舊訂單回填 `discount = 0`、`coupon_code = NULL`，與當時「無優惠碼」的金額一致（`total_amount = subtotal + shipping_fee`）。

### 業務規則與邊界

- 優惠碼查表使用 `hasOwnProperty`，`constructor`、`__proto__` 之類的字串不能被當成優惠碼。
- 優惠碼只接受 ASCII 英數字、`-`、`_`，長度上限 32；其他字元一律視為不存在的優惠碼（避免 `ſ`、`ı` 之類字元經 `toUpperCase()` 變成別的字母）。
- 錯誤訊息不回顯使用者輸入的優惠碼（已知優惠碼的訊息才帶出代碼）。
- 優惠碼驗證在讀取購物車、算出小計之後、建立訂單之前；驗證失敗不會有任何寫入。
- `createOrderFromCart` 維持既有的 transaction，並檢查 `discount` 為不超過小計的非負整數、`shipping.subtotal === subtotal - discount`。

### 顯示

- 訂單詳情頁與後台訂單詳情，在 `discount > 0` 時多顯示一列「優惠折扣（代碼）」，讓「小計 + 運費 = 總計」仍然成立。

### 不在本次範圍

- 後台管理優惠碼、使用次數上限、每人限用次數。
- 前端結帳頁的優惠碼輸入欄位（選做）：本次只提供 API，頁面尚未送出 `couponCode`。
